# 上游密友功能增补

## 2026-11-10：微信图片分享的最近聊天隐藏

微信图片分享进入 `MvvmContactListUI` 的「最近聊天」时，使用 `SelectContactMvvmList` 和独立数据源；主页会话的 SQL 过滤不会覆盖它。现在在该列表的原生预处理之前，根据上游统一密友名单对传入列表制作过滤副本，再交给微信排序、计算分组和构建适配器；不改会话存储或微信保存的原始快照，避免列表位置和实际点击对象错位，也使临时显示时可以恢复。

页面顶部横向「最近转发」也有独立数据来源。仅在其视图初始化期间，对读取结果中的用户名制作过滤副本，让两份原生显示/选择列表都从同一组结果生成；原始最近转发记录以及这些读取接口在其他场景的返回值不修改。

当密友总开关开启、处于隐藏状态，且「主页会话隐藏」或「通讯录隐藏」至少一个开启时，这个选择器会过滤密友；临时显示、总开关关闭或两项都关闭时不做过滤。原始 DEX 已核对 8.0.78（3180）、8.0.79（3182、3200）和 8.0.80（3220）的选择器方法及聊天账号字段；仅对这些准确版本启用，其他版本不会猜测混淆字段。该入口直接使用已核对的版本映射，不增加隐藏联系人功能的 DexKit 缓存项，避免升级后等待重新适配时整个隐藏功能暂不启动。实机结果以本次构建回执为准。

3545173 已完成 Release 构建、同签名覆盖安装和微信重启。实机微信 8.0.80（3220）选取同一密友：隐藏时顶部最近转发及下方最近聊天均不出现，临时显示时两处均恢复；再次隐藏后两处过滤重新生效。相邻普通聊天保留，多选中分别选取顶部和下方的普通聊天后核对对象一致，再取消选择；未发送图片。运行记录确认两处 Hook 均已安装并过滤数据。

这只是微信内部图片分享选择器专项验证；其他微信版本仅完成上面的原始 DEX 静态核对，未在设备上测过，也未覆盖外部相册分享、搜索结果和完整功能回归。实机记录仅保存在本地，不随源码上传。

## 2026-11-10：内屏双栏圆点提示修复

维护分支构建命令：`./Build-UpstreamAddons.ps1 -BuildOnly -ExpectedBranch codex/fix-fold-indicator`，默认 Release。`ExpectedBranch` 只显式指定待核对的分支，原主线默认值保持不变。实机验证需覆盖左主页/右聊天、焦点切换、折叠/展开及后台恢复。

## 3545163 恢复显示与朋友圈独立开关修复

- 临时显示、恢复隐藏、修改名单、通讯录隐藏开关及总功能开关变化时，调用微信原生 AddressLiveList 全量重载。跟踪加载编号与状态版本；加载中再次切换会排队，单次状态最多尝试三次，旧回调不覆盖新状态。通讯录过滤保留原始快照，只替换本次显示输入。
- 临时显示时补齐升级遗留的缺失会话：仅处理首次启用修复时名单中的联系人或具有有效旧快照的联系人。保留旧版恢复完成标记；通过原生接口读写，有行就不重复插入。无快照时仅在本机仍有聊天记录时重建列表条目；完成后不再复活用户随后移除的会话。聊天记录已删除的内容不能恢复。
- “朋友圈隐藏”只控制帖子与新动态提示；“朋友圈互动隐藏”独立控制点赞、评论和互动消息列表。帖子 SQL 现在检查帖子开关；互动 Hook 不再依赖帖子开关，也会在启动时安装、执行时读各自配置。互动仅过滤副本，不删改原始缓存。切换后重新进入朋友圈刷新已显示的页面。

验收：三击显示 → 通讯录出现 → 恢复隐藏后消失；旧会话恢复后再次显隐不重复插入；朋友圈开关四种组合分别为全显示、只隐藏帖子、只隐藏互动、两者都隐藏，临时显示期间两者均放行。实机结果以对应版本的本地验收记录为准。
